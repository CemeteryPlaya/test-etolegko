# speedtest-cli

Консольный скрипт на Node.js для замера скорости скачивания. Он делает серию **последовательных** HTTP-запросов к указанному адресу, дочитывает каждый ответ до конца и выводит:

- время каждого запроса и среднее время запроса;
- общий объём скачанных данных;
- итоговую скорость скачивания.

Внешних зависимостей нет: используются только встроенные `fetch`, `util.parseArgs` и `node:test`.

## Требования

- Node.js **20 или новее** (`node --version`)

## Запуск

```bash
git clone <ссылка-на-этот-репозиторий>
cd speedtest-cli

node bin/speedtest.js <url> [опции]
```

`npm install` не нужен. Тот же запуск через npm:

```bash
npm start -- https://proof.ovh.net/files/10Mb.dat
```

### Опции

| Опция | По умолчанию | Описание |
|---|---|---|
| `-n, --count <число>` | `10` | количество последовательных запросов |
| `-t, --timeout <секунды>` | `30` | таймаут одного запроса, включая скачивание тела |
| `-h, --help` | | справка |

### Пример

## Единицы измерения

| Величина | Единица |
|---|---|
| Время запроса | миллисекунды (**мс**) |
| Объём | **МБ** = 1 000 000 байт (десятичный мегабайт), плюс точное число байт |
| **Скорость (основная)** | **Мбит/с** = 1 000 000 бит в секунду |
| Скорость (дополнительно) | МБ/с = 1 000 000 байт в секунду |

Основная единица — Мбит/с, потому что в ней указывают скорость тарифы провайдеров и сервисы вроде speedtest.net, так что результаты можно сравнивать напрямую. 1 МБ/с = 8 Мбит/с.

## Как считается результат

- **Время запроса** — от отправки запроса до получения последнего байта тела, то есть включает DNS, TCP/TLS-рукопожатие (если соединение не переиспользовано), ожидание первого байта и само скачивание.
- **Среднее время** — среднее арифметическое времени успешных запросов.
- **Объём** — сумма байт тела всех успешных ответов. Тело читается потоком: байты считаются по мере поступления, а весь файл в памяти не хранится.
- **Скорость** = общий объём / суммарное время успешных запросов. Это средневзвешенная скорость. Среднее арифметическое скоростей отдельных запросов давало бы завышенный результат, потому что у быстрых запросов был бы непропорционально большой вес.
- В запросах передаются `Accept-Encoding: identity` (сервер не сжимает ответ, поэтому считаются реально переданные байты) и `Cache-Control: no-cache` (просьба к промежуточным кэшам не отдавать сохранённую копию).
- Ошибка одного запроса (HTTP-статус не 2xx, таймаут, сетевая ошибка) не прерывает серию. Такой запрос выводится как ошибка и не входит в статистику.

## Коды выхода

| Код | Значение |
|---|---|
| `0` | все запросы успешны |
| `1` | хотя бы один запрос завершился ошибкой (статистика печатается по успешным, если такие есть) |
| `2` | неверные аргументы |

## Тесты

```bash
npm test
```

Тесты используют локальный HTTP-сервер, интернет для них не нужен. Они проверяют, что запросы идут строго последовательно, что тело читается полностью, что статистика считается верно, что ошибки и таймауты обрабатываются, а также разбор аргументов и коды выхода.

## Структура

```text
bin/speedtest.js     точка входа CLI
src/args.js          разбор и валидация аргументов
src/benchmark.js     выполнение запросов и подсчёт статистики
src/format.js        перевод в единицы и форматирование
src/cli.js           вывод в консоль, коды выхода
test/                тесты (node:test)
```
